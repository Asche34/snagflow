# Phase 3 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task by task.

**Goal:** Deliver live collaborative web updates, personal notifications and complete manager workflow UX.
**Architecture:** Supabase Postgres Changes signals invalidate server-rendered data; RLS and existing RPCs remain authoritative. Subscribe to visible projects' snags, the open snag's comments/photos, and the authenticated user's notifications. Refresh on subscription/reconnection, focus and online recovery; retain mounted form drafts.
**Tech Stack:** Existing Next 16, React 19, Supabase, Radix, Tailwind and Playwright.
**Spec:** SNAGFLOW_BUILD_PROMPT.md sections 6, 8, 12, 15; Phase 2 handoff.

## Global Constraints

- Preserve Fieldwork styling and shared permissions/workflow contracts.
- Preserve local data; do not reset Supabase or change hosted services.
- Reuse installed dependencies and existing assignment/status controls.
- User authorized routine design choices, implementation, independent review, commit and push to main. Work in the clean existing checkout to reuse installed dependencies and standalone build configuration.

## Review Focus

- Reconnect gaps, channel cleanup and route changes must not leave stale lists/details.
- Remote refresh must retain pending comment/rejection drafts.
- Notifications must remain private and failed reads/writes must be visible.
- Concurrent workflow actions must surface RPC errors without false success.
- Deleted photos/snags and revoked membership must reconcile without leaking old data.
