# Implementation review — 2026-10-29

Scope: delivered database authorization/workflow, shared UI permissions, web auth/data paths, existing tests and CI. Planned missing features are not treated as regressions. This was a code review and targeted hardening pass; no visual browser audit was possible.

## Fixed

1. **Cross-project workflow authorization (high):** missing roles produced SQL NULL, so negative authorization checks could skip rejection. RPCs now fail closed; assignee actions require a current member role. Anonymous execution is revoked.
2. **Audit and notification forgery (high):** clients could call SECURITY DEFINER helper functions directly. Helper execution is now owner-only; authorized workflow RPCs can still call them.
3. **Workflow bypass during creation (high):** members could insert closed/already-assigned snags and forged workflow metadata. INSERT policy now requires initial open state and empty closure/deletion/rejection metadata. Initial assignment is manager/admin-only to active project members/managers.
4. **Deactivated project users retain access (high):** role/membership and colleague helpers now require an active caller profile. Old photo ownership alone no longer authorizes writes after project access is lost. This does not revoke an Auth session or previously issued signed storage URLs.
5. **Permission matrix drift (medium):** assignees can no longer edit someone else's snag details; members can no longer edit/create locations or categories. Administrators without explicit project membership now pass shared detail/work permission checks.
6. **Photo-cap locking regression:** creator-only detail edits exposed the photo trigger's dependency on UPDATE RLS. Its parent locking/counting now executes as definer with an empty search path; INSERT RLS still authorizes uploads. A manager-created, member-assigned concurrency test guards this case.
7. **CI coverage gaps:** the unit job no longer invokes E2E without a server; database tests receive stack credentials and refuse CI skips; SQL regressions run separately; E2E uses its installed bundled browser. Web public build variables are allowed and hashed by Turbo. DB/E2E lint configurations now declare their imported dependencies.

All schema changes are in additive migration `20261029000011_authorization_hardening.sql`; old migrations are unchanged.

## Verification

- Before hardening, 20 of 25 SQL authorization assertions failed against the original migrations on PostgreSQL 16. All 25 pass after hardening, including legitimate member create/edit and manager assignment/approval/audit controls. Fixtures roll back.
- Concurrency reproduction: two assignee uploads against another creator's snag with seven photos produced nine photos with invoker locking; after the fix, one upload failed with `SNAG_PHOTO_LIMIT_REACHED` and the count remained eight.
- Shared unit suite: 28 passing tests. Shared, database-test and E2E packages: lint and typecheck passed.
- The isolated database uses small `auth.uid()` and auth/storage schema shims, not Supabase Auth, PostgREST or Storage services. These checks establish PostgreSQL policy/RPC behavior, not end-to-end API behavior.
- Full dependency installation encountered registry timeouts. Filtered test dependencies installed successfully. Docker/Supabase and web/browser runtime validation were unavailable. Existing DB API tests skipped locally; the new concurrency API test remains to be run with the stack.
- No hosted database or deployment was changed. Apply migrations and run the full DB/E2E gate before deployment or the next feature release.
