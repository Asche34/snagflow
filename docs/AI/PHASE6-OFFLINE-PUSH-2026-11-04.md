## Architecture and behavior

Release blocker: Android1.0.4/code5 automatically closes after login on the user's phone. USB inspection confirms the package/version and163567292-byte installed native-base APK. Its SQLite native library/classes are present, but ReactNativeJS reports `Failed to materialize module 'ExpoSQLite': Shared class NativeDatabase (id 3) is not registered`, followed by the fatal missing-module wrapper. Bytecode inspection of the shipped SQLite58.0.15 AAR shows `SharedObjectRegistry.register(String, Class, ModuleBuilder, boolean)`, while Expo Modules v2 runtime0.2.5 has only the three-argument signature. Its class loader suppresses initialization exceptions, leaving the reserved class ID unregistered. This is a precompiled-library/runtime ABI mismatch, not an absent dependency. Read-only evidence lives under ignored `.superpowers/phase6-device-*.log`; no app data was cleared.

Correction in progress: `expo.autolinking.android.buildFromSource: ["expo-sqlite"]` compiles SQLite with the app's0.2.5 compiler plugin and runtime instead of consuming that incompatible AAR. Expo's actual Android resolver confirms the setting. Prepare1.0.5/code6, same package/signing; no schema/file-format/API change. All90 mobile units, typecheck and lint (zero errors/six existing warnings) pass again. A fresh native build and actual phone login/restart verification are required before claiming success. The1.0.4 repack `98666aa3-3566-4a46-8cd5-8be618a7d275` finished before cancellation could take effect; it retains the faulty native base and is superseded.
