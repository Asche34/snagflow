# SnagFlow mobile

Expo SDK 58 online field app. Auth, project search, assigned work, camera/library capture, continuous capture, native editable markup, fix/review workflow, comments, personal updates and PDF/Excel sharing use the same backend/contracts as web. Phase 5 acceptance still needs a physical device against the hosted project.

From the repository root, install the locked workspace dependencies with `pnpm install --frozen-lockfile`. On the login screen, enter the SnagFlow **App URL** and tap **Connect**. The updated web deployment advertises its public backend configuration automatically; users do not enter keys or rebuild to change servers. Optional environment defaults can be copied from `apps/mobile/.env.example`. Never put a service-role key in mobile. Then run:

```powershell
pnpm.cmd --filter mobile start
pnpm.cmd --filter mobile lint
pnpm.cmd --filter mobile typecheck
pnpm.cmd --filter mobile test
# Run separately from DB/browser fixture suites; uses supabase/tests/test.env.
pnpm.cmd --filter mobile test:integration
```

Use a native development build containing the installed SDK-compatible modules for device acceptance. Do not assume an arbitrary Expo Go version contains the matching Skia build. Android/iOS directories are generated by Expo; configure native permissions in `app.json`. EAS release/distribution profiles remain Phase 7.

Native bundle verification from this directory:

```powershell
pnpm.cmd exec expo export --platform android --platform ios
```

For local browser preview use `pnpm.cmd --filter mobile web --port 8085`. Browser preview exercises the native screen structure and online services, but uses original photos in place of native Skia markup and browser downloads in place of native sharing. It is not physical-device acceptance. The isolated preview test configuration is `e2e/playwright.mobile.config.ts`.

With the preview running, run `pnpm.cmd --filter @snagflow/e2e test:mobile`. Set `MOBILE_E2E_BASE_URL` if it uses a different port (the verified production static preview used 8086). Fixture writes are restricted to loopback Supabase, use disposable projects and must run separately from other database/browser fixture suites.

For a physical phone, localhost refers to the phone itself. Supply reachable LAN addresses for local trials, or HTTPS hosted addresses. Configure the Auth redirect allowlist for exactly `snagflow://auth/callback`; passwordless login uses PKCE and must be requested and opened in the same app installation. Existing web invitation acceptance stays on the canonical web origin. No public signup is offered.

This phase has no offline mirror, background queue or push registration. Keep capture/edit screens open until saves and photos finish. Failed writes retain drafts and stable request identities; restarting or navigating away can discard unfinished local drafts. Review/reopen reasons and required fix photos are enforced by the server.

Deployment approval, access requirements and the physical-device test matrix are in [the Phase 5 handoff](../../docs/AI/PHASE5-MOBILE-2026-11-02.md).

Current Android16 Wi-Fi test addresses, installation instructions and the explicitly approved scoped firewall rule are in [the App URL/LAN handoff](../../docs/AI/MOBILE-APP-URL-LAN-2026-11-02.md). HTTPS is required for public App URLs; private-address HTTP is for local tests only.
